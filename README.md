# k8s-basics

## 👁️ Просмотр и фильтрация подов

| Команда | Описание | Нюанс |
|---|---|---|
| `kubectl get pods` | Список подов в текущем неймспейсе со статусами. | Смотри колонку `STATUS`: `CrashLoopBackOff` = контейнер падает, `ImagePullBackOff` = проблема с образом. |
| `kubectl get pods -n default` | Список подов в неймспейсе `default`. | Всегда явно указывай неймспейс, чтобы избежать путаницы. |
| `kubectl get pods -o wide` | Расширенный вывод: добавляет колонки `NODE` и `IP`. | Полезно для проверки распределения подов по нодам и сетевых настроек. |
| `kubectl get pods -l app=python-http-server` | Фильтрация по лейблу (например, python-http-server). | Самый быстрый способ найти свои поды, игнорируя длинные имена с хешами. |
| `kubectl get pods --all-namespaces` | Поды во всех неймспейсах. | Используй редко: вывод очень длинный. Лучше сужать поиск. |

## 🔍 Детальная информация и диагностика

| Команда | Описание | Зачем нужно |
|---|---|---|
| `kubectl describe pod <имя-пода>` | Подробная информация: события, статус контейнеров, IP, нода. | **Первая команда при проблемах.** В секции `Events` часто пишут точную причину ошибки (например, `secret not found`). |
| `kubectl logs <имя-пода>` | Логи контейнера в поде. | Если приложение падает или не стартует — смотри сюда. |
| `kubectl logs <имя-пода> --previous` | Логи из предыдущей попытки запуска контейнера. | Критично при `CrashLoopBackOff`: текущий контейнер может не успеть написать логи, а в предыдущем они есть. |
| `kubectl logs -f <имя-пода>` | «Хвост» логов в реальном времени (`tail -f`). | Удобно для отладки во время работы приложения. |
| `kubectl logs <имя-пода> -c <имя-контейнера>` | Логи конкретного контейнера (если в поде их несколько). | Твой текущий под, скорее всего, одноконтейнерный, но в будущем пригодится. |

## 🛠️ Взаимодействие с работающим подом

| Команда | Описание | Важное предупреждение |
|---|---|---|
| `kubectl exec -it <имя-пода> -- /bin/bash` | Интерактивная оболочка внутри контейнера. | Работает только если в образе есть shell. В минималистичных образах (distroless, scratch) этой команды не будет. |
| `kubectl exec <имя-пода> -- ls -la /app` | Выполнение одной команды без входа в оболочку. | Удобно для быстрой проверки наличия файлов или прав доступа. |
| `kubectl port-forward <имя-пода> 8000:8000` | Проброс порта из пода на локальную машину. | Полезно для локальной отладки, когда сервис не выставлен через Service/Ingress. |

## 🔄 Управление и изменения

| Команда | Описание | Как использовать в связке с Kustomize |
|---|---|---|
| `kubectl delete pod <имя-пода>` | Удаляет под (он пересоздастся, если управляется Deployment). | Не удаляй поды вручную в проде. В dev можно для быстрой перезагрузки, но лучше `rollout restart`. |
| `kubectl rollout restart deployment <имя-деплоймента>` | Перезапускает все поды деплоймента «мягко» (по одному). | **Правильный способ** обновить поды после изменения секретов или конфигов. |
| `kubectl top pod` | Потребление CPU и памяти подами. | Требует установленного Metrics Server. Полезно для поиска «тяжёлых» подов. |


## Автоматически получить имя пода и посмотреть описание (диагностика)
\$podName = (kubectl get pods -l app=python-http-server -o jsonpath="{.items.metadata.name}")
kubectl describe pod \$podName

## Пробросить порт для локальной отладки
kubectl port-forward deployment/python-server 8000:8000
